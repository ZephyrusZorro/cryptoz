Community search surfaced recurring complaints about opaque P&L, chart limitations, API quotas and inconsistent candle updates. These are qualitative leads, not representative user research or provider reliability evidence. The implementation responds through inspectable formulas, exports, editable chart overlays, provenance and reconnect reconciliation. Technical decisions above rely on primary documentation and actual endpoint checks.

## Why this architecture
The previous monolith tied display to uncontrolled fetch chains and hardcoded narratives. This implementation has independently testable boundaries: provider acquisition, normalized OHLCV, deterministic math, interactive presentation and browser-local state. A bounded in-memory cache, request coalescing and fixed upstreams make the single-owner hosted experience practical. This is not a claim of worldwide scale: a public commercial launch should add shared distributed caching, authenticated quotas, paid data licensing, observability and load testing appropriate to the planned audience.

## Coverage decision
“Every coin” and “better than all existing platforms” cannot be established by a single build. The deliverable exposes the currently returned directory and supported spot venues, shows unavailable coverage honestly, and includes the source and verification evidence for further engineering. Paid derivatives liquidations, ETF flows, on-chain entity attribution, institutional news licensing and all-exchange historical depth are separate provider contracts, not invented free features.
